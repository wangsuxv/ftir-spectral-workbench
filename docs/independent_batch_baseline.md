# 普通光谱独立批量基线处理

v0.3.0 在原位序列工作流旁增加普通光谱工作区。原位模式继续使用既有 `FTIR → baseline → Prepared → 可选 Post-Baseline Smoothing → 2D-COS` 流程；普通模式逐谱处理不相关样品，以粗调结果、最终校正谱和可恢复工作区为终点。

## 启动与选择模式

从仓库根目录运行：

```bash
source .venv/bin/activate
streamlit run ui/streamlit_app.py
```

先在侧栏“数据模式”中选择“原位序列模式”或“普通光谱模式”，再上传数据。两个工作区在同一 session 中独立保存；切换模式不会自动转换输入，也不会清空另一模式的正式结果。本版普通模式通过 Streamlit 界面及 `ftir_workbench.batch` Python API 提供，**没有新增普通批次 CLI 子命令**；旧 `inspect`、`baseline`、`smooth`、`twodcos`、`demo` 等命令仍使用原合同。

## 完整操作流程

1. **普通光谱导入与检查。** 上传一个二列文件、一个宽表，或多个二列/宽表文件。先选默认单位，再逐文件确认 A、%T 或 T，点击“确认单位并导入”。宽表中的每个强度列会成为一个独立条目。检查来源、原列名与列序号、波数范围、点数、方向、编码、分隔符、警告和失败原因。同名文件可以并存，重复上传只标为候选，由用户明确保留或排除。
2. **单位与处理范围。** 选中任意条目，设置它自己的输入单位和一个连续处理范围；默认是该条目的完整域。可选 estimate-only smoothing，以及透过率非正值的显式 floor 修复。控件先写草稿，点击“确认此谱单位与处理范围”后才改变正式输入解释，并使受影响的旧粗细调结果过期。原始数值始终保留。
3. **逐谱粗调。** 选择方法与参数，点击“计算粗调预览”，检查原始吸光度、估计通道、粗基线和校正谱。满意后点击“确认当前粗调”，或“确认粗调并下一条”。可随时切回前一条，继续其独立草稿和正式结果。粗调页可以打包并下载已确认粗调结果。
4. **逐谱细调。** 当前条目必须先有有效正式粗调。设置端点窗口或多锚点方法，计算预览，检查粗调后原始残差、用于拟合的估计残差、细基线、最终结果和锚点诊断，再明确确认。选择不做细调时点击“确认不做细调”。尚未操作细调的条目不能自动视为已完成最终处理。
5. **批量检查与导出。** 选择当前、勾选条目或全部条目，分别打包粗调或最终结果。默认要求所选范围全部就绪；存在缺失、过期、失败或明确排除项时，显示原因并阻止完整范围导出。只有明确选择“仅导出已就绪项”才跳过未就绪项，报告仍逐项列出原因。
6. **保存与恢复。** 在批量页点击“准备工作区下载”，然后下载“保存工作区 ZIP”。通过独立的“恢复普通工作区 ZIP”上传入口点击恢复。恢复成功会替换当前普通工作区，原位工作区保持独立；如需保留当前普通工作，请先保存它。

可以使用 [五条纯合成示例](../examples/independent_batch/) 完成上述流程，其中包含宽表、不同坐标轴和三种输入单位。

## 草稿、预览、正式结果

| 操作或状态 | 含义 | 可用于结果导出 |
|---|---|---|
| 草稿 | 控件编辑或复制后的独立配方，允许保留未完成的编辑及错误提示 | 否 |
| 计算预览 | 对当前条目按其有效依赖运行权威 pipeline | 否 |
| 确认粗调 / 细调 | 仅提交仍匹配当前输入、配方和粗调父级的预览 | 是 |
| 确认不做细调 | 保存明确跳过决策，最终结果复用已确认粗调数组 | 是 |
| 保存工作区 | 保存输入、草稿、正式配方、数组和状态 | 不会自动确认草稿 |
| 批量导出 | 只序列化所选条目的正式数组 | 不拟合、不自动确认 |

只修改草稿，不会覆盖旧正式结果；导出会提示草稿没有使用。确认改变 A 的粗调，只使 A 的旧细调过期，保留其草稿待复核，B 的结果和指纹不变。确认改变单位、范围或估计平滑，会使当前条目的粗细调都过期。相同依赖的重复预览使用工作区内有限缓存；相同粗调的再次确认不会无故使有效细调失效。

每谱业务草稿保存在工作区，不以 Streamlit widget state 为唯一来源。切谱、切页、搜索、过滤、列表顺序和图形缩放不运行 pipeline；图形缩放也不改变计算范围。“当前光谱”与“批量勾选”是两个独立选择。

“复制参数到选中项”默认只复制当前阶段的独立草稿；范围和 estimate-only smoothing 分别通过显式选项复制。输入单位、floor、原始数据、来源身份和正式结果不复制。每个目标先检查范围、点数及锚点覆盖；不自动裁短范围或插值。批量预览逐条读取各自配方，错误隔离，不采用最后一个编辑器的参数处理整批。

## 科学合同

所有数值计算仅调用冻结的 `ftir_baseline.pipeline.run_pipeline`。每次构造一个 `n_spectra=1` 的 `SpectrumSet`，明确固定 `series_mode=independent_locked`、`normalization.method=none`。旧 API 的 `[0.0]` perturbation 仅为内部形状占位，metadata 记为 `not_applicable`；它不是实验扰动，不作为普通结果的时间坐标输出。普通模式不创建 Prepared、不运行 2D、不输出 `for_2dcos` 文件。

粗调使用统一的 `fine.enabled=False, fine.method=none` 配置。细调从同一不可变原始输入，结合已确认准备/粗调配方与当前 fine 草稿，重新运行完整 pipeline，并精确核对粗调父级数组。不会把粗调后校正谱当作 raw 再扣一次粗基线。

开启 estimate-only smoothing 时，细调拟合输入是 `baseline_estimation_spectra − B_coarse`；最终结果仍是未被估计平滑替换的原吸光度减去 `B_coarse + B_fine`。分解图始终使用吸光度。T/%T 仅作为明确标注的派生显示或附加导出；负吸光度及其产生的 >100%T 不静默裁剪。

基线方法沿用原实现：粗调 `none / offset / linear / arpls / asls / airpls / rubberband / pspline_arpls`；细调 `endpoint_window_linear / piecewise_linear / pchip / polynomial`，并有明确跳过入口。多项式阶数仍为 1–3。多锚点中心必须覆盖实际处理域、窗口含实际点且不交叠；端点窗口可以越过域边缘以覆盖端点。诊断来自核心返回结果，UI 不重新拟合。

普通模式复用单谱 QC；缺少峰区的指标显示 N/A。时间连续性、相邻谱变化和扰动趋势不适用，不据列表顺序评价跨样品“时间质量”。负残差等诊断供人工审阅，不触发自动删除、裁负值或自动选参数。

## 文本输入边界

沿用公开 parser/probe，接受 `.csv/.tsv/.tab/.txt/.dpt/.asc/.dat/.xy` 及原有编码、分隔符、表头/preamble 规则。每个文件独立读取，再逐列拆分；不同文件可有不同点数、方向和坐标。缺失、非有限数值或非法轴继续严格报错；不填值、不插值、不自动对齐，也不由文件名数字建立扰动排序。

同一宽表各列拥有独立稳定 ID 和按本列 x/y/单位计算的科学输入 hash。文件与列身份另入来源选择 fingerprint；同值不同来源也不能共享带错 provenance 的结果缓存。展示名称不是身份，改名和列表排序不会改变科学结果。普通原始上传不接收 ZIP；ZIP 仅用于恢复本模式工作区。仪器二进制、Excel、JCAMP 和新行式/长表布局不在本版范围，更多文本说明见 [输入格式](input_formats.md)。

## 结果 ZIP 与宽表

结果包 `artifact_type=independent_baseline_batch`，粗调与最终包分别标明 `stage=coarse/fine`、`is_2d_ready=false`。默认每条一个双列 CSV，另保存吸光度/粗细总基线/校正谱 components、逐条 recipe、单位转换、来源列与父级 fingerprint，以及 `processing_report.csv`、`qc_summary.csv` 和 SHA-256 manifest。CSV 使用 17 位有效数字，保留每谱实际裁剪域及原始轴方向；域外原值不会混入校正列。

只有所选阶段的实际输出 x 数组在长度、顺序和全部坐标上 `np.array_equal` 时，才提供同轴宽表。异轴或反向轴仍可打包每谱 CSV，但不自动重采样为宽表。可额外选择派生 T/%T 副本，校正吸光度主文件始终保留；文件名和 metadata 明确它们不是仪器原始透过率。

默认严格导出不会把 stale fine 混入最终结果。`not_decided` 和 `explicitly_skipped` 分别代表尚未决定与明确跳过；只有后者可用零 fine 分量进入最终导出。结果导出不是工作区备份：恢复原始全域数据和编辑状态请保存工作区 ZIP。

## 工作区格式、安全限额与代码更新

工作区使用独立 `artifact_type=independent_baseline_workspace`、schema `1.0`，保存原始文件字节、解析选项、源/列映射、稳定 ID、全部草稿、正式配方和数组、父级关系、显示顺序及错误信息。预览数组不保存，恢复后需要重新请求预览。未完成编辑中的缺失单元格保存为 JSON null，错误提示保留，不悄悄变成已确认配方。

恢复使用严格 JSON 和非 pickle NPY（`allow_pickle=False`），检查 manifest、成员集合、源文件 hash、重新解析后的列映射、数组 hash、stage/parent fingerprint 与分解恒等式；恢复时不重跑 baseline pipeline。读取限制为：

| 限制 | 上限 |
|---|---:|
| ZIP 压缩大小 | 256 MiB |
| 成员数量 | 20,000 |
| 单个解压成员 | 64 MiB |
| 全部解压成员大小 | 512 MiB |

拒绝重复成员、不安全路径、绝对路径/路径穿越、目录或符号链接、加密成员及不支持的压缩方式。SHA-256 用于完整性校验，**不是身份认证的数字签名**。这些是工作区 reader 限额；浏览器/Streamlit 上传配置可能另有更低的上传限制。

实现和数值依赖版本计入 fingerprint。保存的旧实现结果可以在结构和血缘验证通过后载入，但会注明“来自保存的旧实现，未由当前 pipeline 重新计算或确认”；不得把恢复误称为当前环境复算通过。旧细调历史仍保存，并根据父级标明 stale。

**代码更新前先保存工作区，随后停止并重新启动 Streamlit，再恢复 ZIP。** 实现 fingerprint 在进程内缓存，代码模块和内存对象也有各自生命周期；Streamlit 热重载不能作为工作区迁移方案。需要当前实现正式结果时，应重新预览并明确确认相应阶段。
